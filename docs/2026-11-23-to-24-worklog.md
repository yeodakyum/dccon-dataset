# 2026-11-23~24 디시콘 추천 실험 기록

최근 대화와 내가 보낼 말을 입력하면 상황에 맞는 디시콘을 순서대로 보여주는 게 목표였다. 기존 합성 주석 378개로 검색기를 먼저 만들어 보고, 이미지에서 직접 뽑은 주석으로 320개짜리 파일럿을 따로 만들어 검색어 생성과 후보 선택을 비교했다. 11월 23일에 시작해 24일 새벽까지 이어진 프로젝트 채팅과 저장소 산출물을 기준으로 정리했다. 사람 평가를 수집하기 전의 기록이다. 원문 검색에서 반대 맥락의 콘이 상위에 오르고, 소형 모델은 화자를 혼동하거나 어울리는 콘이 없는 상황에서도 선택하는 문제가 반복됐다.

## 1. 기존 합성 주석 378개로 검색 실험

주간 데이터는 100개 패키지, 스티커 레코드 8,245개, 다운로드 성공 이미지 8,218개였다. 그중 합성 주석과 원본을 함께 쓸 수 있는 378개로 시작했다.

- **설명 검색.** 이미지 설명, 이미지 속 문구, 용례 태그를 콘당 한 문서로 합쳐 `intfloat/multilingual-e5-small`로 384차원 벡터를 만들고, 정규화한 벡터를 FAISS 내적으로 비교했다. Tk 창을 띄울 때 Python이 종료돼 브라우저 GUI로 바꿨다. GUI에서 E5에 실제로 들어가는 `query:`와 `passage:` 텍스트를 펼쳐 볼 수 있게 했다.
- **예문·상황 검색.** `sticker_message.text` 1,890개와 용례별 `context`, `fit_reason`, `usage_tags`를 합친 상황 문서 1,890개를 각각 인덱싱했다. 같은 콘이 여러 번 나오면 점수가 가장 높은 용례를 사용했다. 예문·상황 상위 20개의 역순위 점수에 이미지 문구 일치를 더하는 방식과, 최근 대화를 답장에 붙여 상황을 검색하는 방식도 붙였다.
- **원본 이미지 검색.** SigLIP 2로 이미지 378개를 인덱싱했다. 투명 영역은 흰색 배경에 합성하고 GIF는 첫 프레임을 썼다. 채팅 원문과 사람이 적은 표정·동작 설명을 같은 이미지 인덱스에 넣어 비교했다. 첫 검색 타임아웃은 단일 스레드 설정으로 다시 실행해 확인했다.
- **로컬 SLM 검색.** Ollama의 `qwen3.5:2b`를 연결했다. 최근 대화와 답장에서 반응 의도를 만들어 E5 사용 상황을 검색하는 경로와, 표정·동작을 만들어 SigLIP 2 이미지를 검색하는 경로를 만들었다. 초기에 프롬프트 예시를 반복해 예시를 뺐고, 이후에도 지시문 반복이 관찰됐다. 로컬 Qwen3.8-27B와 KURE-v1은 비교 후보로만 검토했다.
- **브라우저 확인.** 파일 복구, 친구 지각, 결승 진출 3건을 넣었다. 예문, 상황, 혼합, 최근 대화 포함, 기존 설명, 원본 이미지, SLM 반응 의도, SLM 표정·동작의 8개 방식이 각 입력에서 서로 다른 콘 5개씩을 표시했다. 결과 화면 네 장과 방식별 1위 ID를 남겼다. [파일럿 1 상세 기록과 스크린샷](../experiments/pilot1/2026-11-23-search-experiments.md)

설명 검색에서 `와 이걸 진짜 해냈다고?`의 1위는 `죄송해요...`였고, 사람이 감탄·축하 의도로 바꾸자 `천재인감!!`가 1위였다. 예문 검색은 `지금 말 걸지 마 나 한 문제 남음`에 `말 걸지 마 한 개 더 집는 중`을 1위로 올렸다. SigLIP 2에서도 집중하는 모습을 설명했을 때 화난 캐릭터가 1위였다. 같은 `됐어 ㅋㅋ`에 파일 복구와 지각 문맥을 붙이면 문맥을 쓰는 세 경로의 1위가 달라졌지만, SLM은 복구에서 안도나 도움을 사양하는 뜻을 놓쳤고 지각에서는 `뚱뚱`을 출력했다.

검색기와 GUI, 실험 기록, 스크린샷은 기존 대화에서 순서대로 `a4dbc8b`, `d03737a`, `054e05a`로 main에 푸시했다.

## 2. Groq 이미지 태깅 실험실

이미지 없이도 제목과 패키지 메타데이터를 써볼 수 있는지 먼저 봤다. 스티커 8,245개 중 개별 제목이 숫자만인 항목이 4,918개(59.6%)였다. 제목만으로 쓰임을 추정하기 어려운 경우가 많았고, 기존 합성 주석도 이미지나 밈을 놓친 채 그럴듯한 대화를 만드는 문제가 있었다. Qwen을 20대 남성 말투의 에이전트에 활용하는 방향을 논의했다. 에이전트 학습은 진행하지 않았다.

- **태깅 GUI.** 정지 이미지 5,127개에서 제목·ID로 검색하거나 무작위 선택하고, 프롬프트를 수정해 Groq `qwen/qwen3.8-27b`를 호출하는 화면을 만들었다. API 키를 웹에서 입력하고 JSON, 응답 시간, 토큰 수를 볼 수 있게 했다. TLS 인증서와 기본 HTTP 요청의 403을 수정해 인증 단계까지 도달하는 것을 확인했다. 이후 사용자가 Qwen의 태깅 출력에 대해 예상보다 잘 된다고 평가했다.
- **태깅 형식.** `image_text`, `visual`, `reactions[].intent`, `reactions[].evidence`, `uncertain`을 받는다. 이미지에서 읽거나 관찰한 단서와 반응 해석을 구분했고, 배치에서는 이미지 바이트 대신 콘 ID, 원본 경로와 해시를 저장한다. 콘별 체크포인트로 중단 후 재개할 수 있게 했다.
- **GIF 지원.** GIF 3,060개를 따로 고르는 필터와 원본 재생, Groq 전송 미리보기를 추가했다. 재생 시간 0·25·50·75·100%의 장면을 한 PNG에 이어 붙였다. 프롬프트에서 칸들을 한 GIF의 시간순 장면으로 설명하고, 움직임과 자막의 변화를 `visual`에 요약하게 했다. 전송 형식은 모의 요청으로 확인했고, 이후 혼합 배치에서 실제 GIF 주석을 받았다.
- **비용과 실행 위치.** 당시 가정으로 성공 이미지 8,218개를 한 번씩 태깅하는 API 비용은 약 $17~21, 정지 이미지 5,127개는 약 $12~14로 추산했다. RTX 3090에서 4비트 Qwen3.8-27B 비전 모델을 실행하는 구성은 검토했고 실측은 하지 않았다. 대화마다 전수 이미지 토너먼트를 돌리는 방식도 검토했으며, 3장씩 비교하는 경우의 이론치가 대화당 약 1시간 41분이었다. E5 상위 9개만 세 조로 나눠 비교하는 안은 실행하지 않았다.
- **웹 이미지 검색.** Groq의 이미지 분석과 별개로 Daum·네이버·Brave의 이미지 검색을 비교했다. 제목과 이미지 문구를 이용해 밈 원본이나 참고 이미지를 찾는 용도로 검토했으며 검색 API를 GUI에 연결하지 않았다.

## 3. 파일럿 2 — 정지 이미지와 GIF 320개

28개 패키지에서 정지 이미지 16개와 GIF 16개를 뽑아 Groq로 주석을 만들었다. 이 32개를 재사용해 100개 패키지에 걸친 정지 이미지 160개와 GIF 160개로 늘렸다. 저장된 토큰을 당시 단가로 환산하면 32개는 약 $0.07, 320개는 약 $0.68이다. 병렬 전환 중 일부 요청이 중복됐으므로 실제 청구액은 이 합계와 다를 수 있다. 최종 JSONL에는 콘마다 한 행씩 저장했다. 초기 32개 표본에선 SLM이 지각 상황 검색어로 ‘검색 결과가 없습니다’를 생성하는 사례가 있었다.

같은 320개 주석에서 이미지 문구, 반응 의도, 시각 묘사를 임베딩했다. 비교 GUI는 **이전 대화**와 **입력할 대화**를 받고 아래 결과를 나란히 표시한다. SLM은 로컬 `qwen3.5:2b`다.

| 방식 | 동작 | 8건 중앙 응답 시간 |
| --- | --- | ---: |
| FAISS | 두 입력을 이어 붙여 상위 5개를 표시 | 0.1초 |
| SLM output → FAISS | SLM이 만든 반응 태그와 시각 묘사로 검색해 상위 5개 표시 | 4.5초 |
| FAISS → SLM choose | 원문 검색 상위 10개의 주석을 보고 최대 3개 선택 | 8.3초 |

- **결승 진출과 숙제 파일 삭제.** 같은 `와 진짜?`에 후보 선택은 두 상황 모두 웃는 `진짜야?` GIF를 골랐다. 검색어 생성 방식은 파일 삭제를 당황하는 반응으로 풀어 당황하는 콘을 1위에 올린 사례가 있었다.
- **위로.** 원문 검색 상위 10개에 위로 태그 콘이 없었다. SLM 검색어는 안아주는 GIF를 3위로 찾았다. 원문 후보를 받은 SLM은 `니 알아서 쳐 먹어` 콘을 첫 번째로 골랐다.
- **회의실 안내.** 답장에 시간과 장소만 있었는데도 후보 선택은 실망·좌절 콘을 골랐다. 빈 목록을 허용했지만 합성 대화 8건 모두에서 최소 하나를 골랐다.
- **프롬프트 재시험.** SLM 출력을 주석과 같은 짧은 반응 태그 최대 2개와 표정·동작 한 구절로 맞췄다. 예시로 준 `위로·공감`이 다른 대화에도 반복돼 예시를 빼고 JSON 스키마를 적용했다. 8건 모두 형식은 맞았고, 영어 태그, 파일 삭제 상황에서의 화자 혼동, 일정 안내에 태그를 붙이는 문제는 남았다.

## 4. 한국어 임베딩 A/B

`multilingual-e5-small`과 이를 한국어 질의–문서 쌍으로 미세조정한 `dragonkue/multilingual-e5-small-ko`를 비교했다. 320개 주석, 384차원 정규화, E5 접두어, FAISS 내적 검색을 고정했다. 이전 대화의 원문 8개와 고정 SLM 출력 8개, 은어·표준어 4쌍을 합쳐 24개 검색어를 돌렸다.

상위 10개 겹침은 원문·SLM 출력 16건에서 평균 4.94개, 은어·표준어 8건에서 평균 4개였다. `ㅇㅇ 알빠노`는 기존 E5에서 강한 부정 콘, 한국어 E5에서 감탄하는 `개쩌누`가 1위였다. 피로를 표현한 은어는 두 모델 모두 상위 3개에 피로 태그가 없었고, 같은 뜻의 표준 표현에서는 둘 다 `수고했어, 힘들겠다` 태그 콘을 1위로 올렸다. 한국어 튜닝으로 순위는 달라졌고, 은어 해석이나 문맥 적합성이 일관되게 개선됐다는 근거는 얻지 못했다.

기존 E5는 8767, 한국어 E5는 8770으로 비교했다. 마지막 대화에서 GUI가 작동하지 않는다는 보고가 있었고, 로컬 HTML 파일을 직접 열어 검색 API에 연결되지 않았을 가능성이 제기됐다. 해당 탭에서 복구됐는지는 확인되지 않았다. 실행 명령은 파일럿 2 README에 있다. [24개 쿼리별 검색 결과](../experiments/pilot2/results/embedding-ab.json)

## 5. Pilot 3 통합 GUI와 모델 비교

Pilot 1의 검색 8가지와 Pilot 2의 검색 3가지, 이미지 태깅, 두 표본의 배치 실행, 기존 실험 기록을 한 화면에 연결했다. 텍스트 인덱스는 선택한 모델과 컬렉션마다 첫 요청에서 만들고 재사용한다. 원본 이미지 검색은 SigLIP 2를 사용한다.

- **E5-small과 KURE-v3.** 기존 모델은 `intfloat/multilingual-e5-small` 384차원이다. `nlpai-lab/KURE-v3`는 기본 2,048차원 중 1,024차원을 사용했다. 실제 320개 주석에서 양쪽 모두 결과를 반환했다. 이 확인은 GUI와 인덱스 동작을 확인한 것으로, 두 모델의 추천 품질을 비교한 고정 평가셋은 없었다. 공개 한국어 검색 벤치마크의 KURE-v3 점수는 이 프로젝트의 추천 점수로 사용할 수 없다. [E5-small 모델 카드](https://huggingface.co/intfloat/multilingual-e5-small) · [KURE-v3 모델 카드](https://huggingface.co/nlpai-lab/KURE-v3)
- **Ollama 복구.** Mac 재시작으로 임시 모델 캐시가 사라졌고, 별도로 Homebrew Ollama의 구조화 응답 요청이 HTTP 501을 반환했다. 캐시를 저장소 안의 로컬 데이터 경로로 다시 받았고, 501이면 구조화 형식 옵션을 빼고 다시 요청한 뒤 기존 JSON 검증을 적용했다. 실제 로컬 Qwen에서 4개 SLM 경로가 결과를 반환했다.
- **Groq Qwen 전환.** `qwen/qwen3.8-27b`를 로컬 Ollama 대신 선택할 수 있게 했다. 합성 주석의 반응 의도·표정 및 동작 검색, 이미지 주석의 검색어 생성·후보 선택에 적용했다. 네 경로와 키 처리를 모의 응답으로 검증했다. 실제 Groq 기반 추천 호출과 로컬 모델 대비 추천 품질은 확인 전이다. 앞서 실행한 이미지 태깅 배치에서는 실제 Groq 응답을 받았다.
- **파일 복구.** iCloud 오프로드 때문에 데이터 읽기가 멈추는 문제가 있어 저장소를 홈 폴더로 옮겼다. 이동 준비본의 원본 이미지 8,218개를 매니페스트의 SHA-256과 대조했다.

## 6. KOTE 감정 태그와 예문 검색

320개 표본의 자막·시각 설명·반응 주석을 바탕으로 각 콘에 KOTE 감정 43종 중 서로 다른 3개씩, 총 960개를 골라 `kote_emotions`에 추가했다. 같은 태그를 로컬 배치 체크포인트에도 반영했다. 이 태그는 기존 주석을 읽고 고른 값이다. 해당 단계에서 KcELECTRA 추론과 원본 이미지·GIF 재검수는 수행하지 않았다. 감정 단서가 적은 콘에도 3개가 붙어 있으므로 정답 라벨로 쓰기 어렵다. [KOTE 저장소](https://github.com/searle-j/KOTE) · [320개 태그 포함 주석](../experiments/pilot2/results/annotations-320.jsonl)

Pilot 3의 **예문 + 감정**은 KOTE KcELECTRA로 보낼 말의 상위 감정 3개를 추론한다. 콘별 합성 예문을 우선 검색하며, 예문이 없으면 이미지 문구, 반응 태그, 시각 묘사 순으로 쓸 수 있는 텍스트를 고른다. 텍스트 유사도에 일치한 감정 점수의 합을 3으로 나눈 값의 0.10배를 더해 상위 5개를 표시한다.

“와 드디어 해냈다! 너무 기뻐 ㅋㅋ”에서 즐거움/신남 98.1%, 기쁨 97.1%, 행복 90.5%가 나왔다. 추천 5개에 세 태그가 모두 붙어 있었다. 가점이 감정 일치를 순위에 반영하는지 본 한 건이다. 가점이 없는 검색과의 적합성 비교, 감정이 약하거나 보낼 말만으로 뜻을 알기 어려운 사례는 평가 전이다. [사용한 KOTE 모델](https://huggingface.co/searle-j/kote_for_easygoing_people)

## 7. 실제 사용 사례와 후속 평가 검토

- **실제 댓글 수집.** 공개 글·댓글에서 디시콘 URL의 `no` 값을 기존 매니페스트의 `source_url` 또는 `item_raw.path`와 맞춰 `sticker_id`를 연결하는 안을 논의했다. 3~5개 갤러리에서 공개 글 약 100개와 댓글 첫 페이지를 보고, 매칭 사례 20~30건이 나오는지 점검하는 규모를 잡았다. 글 제목·본문 또는 부모 댓글과 콘 ID, 출처를 보존하고, 동일 글의 동일 콘 반복은 묶되 다른 글에서의 재사용은 남기는 안이다. 현재 댓글에서의 추출과 매칭은 실측 전이다.
- **웹 검색으로 밈 용례 찾기.** 실제 사용 맥락을 검색해 고양이 콘을 달아 달라는 게시글까지 찾았다. 검색 결과에 식별자가 없었고 원문 댓글을 열지 못해 기존 데이터셋의 콘과 연결하지 못했다. [검색에서 찾은 게시글](https://gall.dcinside.com/mgallery/board/view/?id=cpyv22&no=1596481&t=cv)
- **카톡 예문 활용.** 최근 2~4턴의 대화와 대상 답장을 질의로 삼고, 콘마다 여러 예문을 임베딩해 FAISS로 검색하는 안을 검토했다. 같은 콘에 매칭되는 예문을 묶은 뒤 LLM에 이미지 설명·문구·상위 예문을 넘기면 매번 원본 이미지를 분석할 필요가 줄어든다. 상황이 비슷하지만 반응이 다른 대화도 평가에 포함하는 안이다. 실제 카톡 데이터 가공과 후보 선택 실험은 진행하지 않았다.
- **스키마.** 크롤러 매니페스트에 이미지 관찰·반응 주석, 콘당 여러 사용 예시, 평가 질의와 후보별 적합성 판정을 연결하는 안을 정리했다. 모델·프롬프트·이미지 해시·GIF 프레임·검토 상태를 기록하고, 새 콘에 대한 일반화 실험은 패키지 단위로 분리하며 동일 해시가 분할을 가로지르지 않게 하는 설계다.
- **유사 연구.** PEPE의 실제 트윗–GIF 답장과 태그·대조학습, Selecting Stickers의 대화–후보 적합성 분류, IGSR의 문맥 기반 의도 추론과 검색 학습, PerSRV의 시각 주석·OCR·검색 기록을 활용한 검색과 순위화를 검토했다. [논문 링크와 비교](../experiments/pilot2/EXPERIMENTS.md#유사-연구)
- **사람 평가와 재정렬.** 별도 채팅 40~60건에 여러 방식의 후보를 합쳐 실제 이미지나 GIF를 보고 적합·애매·부적합을 표시하는 안을 논의했다. 같은 답장에 맥락만 바꾼 쌍과 어울리는 콘이 없는 입력을 포함하고, 후보 포함 여부·1위 적합성·선택 보류를 각각 측정하는 방식이다. 원문·SLM 검색 후보 합치기, 태그 선택지 고정, 대화와 콘을 한 쌍씩 채점하는 재정렬 모델은 비교 후보였으며 평가셋 제작과 재정렬 학습은 진행하지 않았다.

판정 근거는 합성 채팅, 검색 순위, 이미지 문구와 주석이다. 카톡이나 실제 댓글을 대상으로 한 적합성 평가 결과는 아직 없다.
